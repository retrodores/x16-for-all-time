# X16 For All Time port specification

This document describes the launcher behavior and X16 Files interface implemented by X16 For All Time for Windows. It is intended for developers building a native Linux or macOS launcher. The Windows implementation is the reference. A port can choose its own UI, packaging, and settings format.

## Launcher behavior

| Area | Behavior |
| --- | --- |
| Start | Save, search, and launch local program entries. Each entry has a display name, a PRG path, and either inherited Start defaults or its own emulator and launch options. Duplicate an entry to keep multiple setups for one PRG. Removing an entry keeps its files. |
| Local programs | Accept local `.prg`, `.bas`, and `.zip` files. Reference loose programs in place and import ZIPs using the archive rules below. Keep the imported files when the entry is saved. Canceling the add operation discards the import. **Run once** remembers its last successful emulator and launch settings independently of Start. Fall back to Start defaults when the remembered emulator is unavailable. Let the user choose an emulator, a profile, or custom settings without saving an entry. Keep temporary ZIP contents until the emulator exits. |
| X16 Files | Browse and search the catalog, clear the search independently of the download filter, and show a count that follows the search and filter. Provide Expand all and Collapse all for the current results on both X16 Files and SD Card Kit. Open project pages from the catalog. Offer explicit refresh, install or reinstall to Start, and download and launch. |
| Emulators | Register an existing emulator executable or install platform-appropriate builds side by side. Allow multiple builds, including forks. Each build can have named profiles and a default profile. On first run with no emulator registered, open emulator setup and show a dismissible prompt to install or register a build. |
| Profiles | Use a profile to prefill settings for a Start entry or Start defaults. Saved settings are a copy. Entries set to use Start defaults follow that configuration. Explicitly assigned entries keep their saved settings if the emulator is removed. Use the working Start default or the first available emulator in registration order as a fallback. Managed X16Emu installs create presets for both 65C02 and 65C816 at 2, 4, and 8 MHz and 512, 1024, 1536, and 2048 KiB. New presets and the new Default profile use 2× display scale. Preserve edited profiles on reinstall. |

A Start entry needs a usable emulator and a PRG to launch. Register or install an emulator to unlock Start and the catalog tabs in the Windows client. The Windows client keeps settings and managed programs in per-user storage. A port can use XDG directories on Linux and Application Support on macOS. Give each imported or downloaded package its own directory to avoid overwriting files shared by existing entries.

## X16 Files catalog

Fetch the versioned launcher feed with HTTP GET. The feed is generated by the X16 Files project from its program metadata. Use the generated feed as the launcher interface. Independent client authors should follow the catalog project's data-use terms when integrating or redistributing its data. [Launcher feed](https://x16files.com/directory/data/launcher.json) · [Feed generation and data-use terms](https://github.com/retrodores/x16files.com#x16-for-all-time-catalog-feed)

The response is a JSON object with `schema_version: 1` and a `programs` array. Reject unsupported schema versions, missing program arrays, and blank or duplicate `appid` values. Compare IDs as case-sensitive strings. Keep the last successfully loaded list available if refresh fails. Explicit refresh should request revalidation and reapply the current search and filter.

| Program field | Type | Meaning |
| --- | --- | --- |
| `appid` | String, required | Stable catalog ID. Use it to associate a catalog entry with its installed Start entry. |
| `name` | String, optional | Display title. Fall back to `appid` if blank or omitted. |
| `category` | String, optional | Display and search field. |
| `author` | Object, optional | The display and search name is `author.name`. |
| `version`, `description` | Strings, optional | Display metadata. |
| `page_url` | String | Project page URL. Use a usable HTTP or HTTPS URL for the browser action. |
| `package` | Object, optional | A single downloadable distribution. |
| `packages` | Array, optional | Several distributions. A non-null array takes precedence over `package`, even when empty. |

Use the program name, category, and author name for case-insensitive search. An entry is downloadable if it has at least one supported package. Entries without supported packages remain browsable. The visible count includes only rows that match both the search and the active filter.

| Package field | Type | Meaning |
| --- | --- | --- |
| `url` | String, required | Absolute HTTP or HTTPS download URL with a host and no embedded credentials. It may be extensionless, as with forum attachments. |
| `format` | String, required | `"prg"` for a loose PRG or `"zip"` for an archive. Use the declared format. |
| `prg` | String, optional for ZIP | Exact, case-sensitive startup path relative to the archive root. Use forward slashes for nested paths. Omit the field to let the launcher select or ask. |

A feed entry with one ZIP package looks like this.

```json
{
  "schema_version": 1,
  "programs": [
    {
      "appid": "meteordefender",
      "name": "Meteor Defender",
      "category": "games",
      "author": { "name": "voidstar78" },
      "version": "1.0.0",
      "page_url": "https://x16files.com/directory/games.html#app-meteordefender",
      "package": {
        "url": "https://github.com/voidstar78/METDEFX16/releases/download/v1.0.0/METDEFX16_V1.ZIP",
        "format": "zip",
        "prg": "METDEFX16.PRG"
      }
    }
  ]
}
```

The declared format determines whether the launcher offers a download. The server may deny the request, and a package may fail archive or PRG checks after download. For HTTP 403, report the status, display the original URL, and offer to open it in the user's browser. A PRG or ZIP obtained there can be imported through Add PRG. Never require a digest for a catalog package. Emulator release assets use a separate download flow.

### Install and launch from the catalog

- **Install to Start** downloads the selected package and records its PRG path with the catalog ID. The emulator registration unlocks access to the catalog on Windows.
- **Reinstall to Start** updates the PRG path for the matching catalog ID and keeps the entry's name and launch settings. A failed download, invalid archive, or canceled picker leaves the existing entry intact.
- **Download and run once** fetches the package and launches its PRG with run-after-load enabled and leaves Start entries as saved. Use the same selection as Start. Use a working explicit assignment for an existing Start entry, then working Start defaults, then the default profile of the first registered emulator with an available executable. Prompt for emulator setup if none are usable.
- When several supported packages are offered, let the user select one before downloading. A double-click on a downloadable catalog row is a shortcut for install or reinstall.

## PRG and ZIP handling

1. Download into a staging directory. Keep a direct PRG's URL filename when it is usable. The reference client uses `program.prg` for an extensionless or unusable filename.
2. For a ZIP, extract the whole archive and preserve its hierarchy and companion files. Check that each destination stays under the extraction root. Reject unsafe paths, conflicting destinations, and entries that could escape the root via filesystem links.
3. If the feed supplies a startup path, require an exact match. Otherwise find PRGs by case-insensitive extension, including in nested folders. Select the sole PRG automatically. For several, show their relative paths in a picker. A ZIP with no PRG is an error.
4. Commit the chosen PRG path only after successful download and extraction. Clean up data staged by failed or canceled operations. Keep prior installations usable until their replacements are ready.

## X16Emu launch contract

Run the configured executable with the chosen PRG's containing directory as the working directory. Pass an absolute PRG path after `-prg`. Pass `-run` for **Run PRG** and omit it for **Load PRG**. X16Emu uses a comma in a PRG argument to introduce a load address. The reference client rejects a PRG path containing a comma.

| Setting | X16Emu argument |
| --- | --- |
| CPU | `-c02` or `-c816` |
| Clock and banked RAM | `-mhz <MHz>`, `-ram <KiB>` |
| Display scale and fullscreen | `-scale <factor>`, `-fullscreen` |
| ROM and SD card image | `-rom <path>`, `-sdcard <path>` |
| Host filesystem root | `-fsroot <directory>` |
| GIF recording | `-gif <path>` |

Omit unset overrides so the emulator can apply its own defaults. Resolve relative GIF paths against the PRG folder. The Start recording toggle can override the saved GIF path for one launch. A blank override uses `demo.gif`. Allow build-specific extra arguments and prevent them from conflicting with arguments the launcher already supplied. Provide a command preview for troubleshooting. On Linux and macOS, pass an argument vector and working directory directly to the process API using the platform's quoting conventions for any command copied to the clipboard.

Use an emulator binary and corresponding assets for the host OS and architecture. Registration of an existing native build is sufficient to launch programs. If the port offers installer-managed builds, use the platform's official X16Emu release assets, keep accompanying files, and check the published digest when provided. [Official X16Emu releases](https://github.com/X16Community/x16-emulator/releases)
